# Обновление игры через Rojo

Rojo переносит скрипты из этой папки в открытое место в Roblox Studio.
Здесь он настроен так, чтобы **ничего, кроме нужных скриптов, не трогать**:
модели, детали, звуки, интерфейсы и остальные скрипты остаются как есть.

## Один раз: установить

1. **Rojo.** Проще всего через [Rokit](https://github.com/rojo-rbx/rokit): в папке репозитория выполни
   `rokit install`, версия указана в `rokit.toml` (7.4.4). Или скачай `rojo` со страницы
   [релизов](https://github.com/rojo-rbx/rojo/releases) той же версии.
2. **Плагин для Studio:** `rojo plugin install` (или найди «Rojo» в магазине плагинов).

## Каждый раз: обновить игру

> Сначала потренируйся на **копии** места (File → Save to File As… или отдельное тестовое место).
> Rojo перед первой синхронизацией показывает список изменений: просмотри его, прежде чем соглашаться.

1. **Свежая копия места для проверки классов.** В Studio: File → Save to File As… →
   формат **.rbxlx**, например `TR2.rbxlx`, в папку репозитория (в git он не попадёт, см. `.gitignore`).
2. **Собрать проект:**
   ```
   python3 tools/make_rojo_project.py --place TR2.rbxlx
   ```
   Скрипт напишет `default.project.json` и выведет, что будет синхронизировано (`+`)
   и что пропущено (`-`) с причиной.
3. **Запустить Rojo:** `rojo serve`
4. **В Studio:** вкладка Plugins → Rojo → **Connect**. Проверь список изменений и подтверди.
   Скрипты обновятся. Пока Rojo подключён, правки в файлах сразу попадают в Studio.
5. **Удалить старое** (Rojo сам ничего не удаляет): View → Command Bar, вставь
   `tools/cleanup_old_scripts.lua` целиком, Enter. Сначала это пробный прогон: в Output будет
   список. Поменяй в начале `DRY_RUN = false` и запусти снова. Отмена — Ctrl+Z.
6. **Ручная настройка** из `CHANGES.md` (например, детали `BoxPickup` и `BoxDelivery` для работы с
   коробками), плейтест, публикация.

## Что синхронизируется

- Только скрипты, которые **изменены или добавлены** в репозитории после выгрузки из Studio.
  Остальные в репозитории могут быть старше, чем в Studio, поэтому их Rojo не трогает.
  Синхронизировать вообще всё: `--all` (когда репозиторий станет главным местом для кода).
- Если скрипт **меняли в Studio после выгрузки**, он пропускается с пометкой — сравни вручную.
  Перезаписать всё равно: `--force`.
- Без `--place` в проект попадают только скрипты, лежащие прямо в сервисах
  (`ServerScriptService`, `ReplicatedStorage`, `StarterPlayerScripts`): им не нужны классы
  родителей. Такой `default.project.json` уже лежит в репозитории — его можно запускать сразу,
  но скрипты внутри инструментов, магазинов и NPC тогда придётся обновить вручную
  (список печатает генератор).

## Почему так сложно

- Если Rojo считает объект другим классом (магазин — Part, а в проекте Folder), он **удаляет
  его и создаёт пустой**. Поэтому классы всех родителей скрипта берутся из твоего `.rbxlx`.
- В синхронизируемых папках Rojo по умолчанию удаляет всё, чего нет в проекте. Здесь везде
  стоит `$ignoreUnknownInstances: true`.
- Два скрипта с одинаковым именем у одного родителя (такие есть в дверях домов) Rojo не различает —
  они пропускаются.

## Имена файлов

По правилам Rojo класс скрипта задаётся расширением:
`.server.lua` — Script, `.client.lua` — LocalScript, `.lua` — ModuleScript.
`tools/extract_rbxlx.py` теперь тоже называет файлы так.
